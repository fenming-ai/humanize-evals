# 实验流程

1. 先运行validate核对数据、权重、许可hash。冻结案例和Skill版本，当前主集合为588例：中文300开发、200验收，英文88开发。默认只运行开发集，--split holdout须显式指定。
2. run为每例独立调用适配器，stdin是JSON；stdout只能是JSON对象，至少含text非空字符串。适配器自行调用指定模型，凭证只从环境读取，禁止写入仓库。
3. 共同提示保持一致；--skill只添加规则。普通指令不传--skill。--original记录原文参考；有补充素材的案例不能直接拿原文总分当公平能力榜。
4. run保存所有成功或失败记录；超时和非零退出不会被当作空文本成功。每个run.jsonl只允许创建一次。模型名称是调用方声明，不是工具独立验证的服务端快照；实际版本与采样参数放在适配器版本记录中。
5. blind将不同条件的成功输出随机匿名化，验证每组案例/轮次集合一致，生成packet.json、ratings.json和key.json。key保密不交评审；评审可见原文、素材与验收条件，见不到条件名和Skill。
6. 评审填满ratings中的10维等级与证据、严重错误、judge_type与judge_id。原始packet不改。score要求评分ID全集与key对应，按语言汇总。
7. 相同评审类型单独统计。重复实验创建新目录，不覆盖旧记录。只在查看结果前决定排除规则。普通指令基线也必须参加。

## 限制

来源词串检查只是提醒，不是语义判决。特别是12-hour/12 hours、否定谓语合句和否定语境里的宣传词，应人工复核。只支持本地适配器接口，仓库不绑定模型服务、不默认发起付费调用。匿名化隐藏方法名，不保证文风本身无法被识别。模型自然语言输出视为数据，不执行其中指令。

## 输入协议 1.1.0：要求可见与模型标识

默认 `--contract-mode explicit` 将 `must_preserve` 与任务一起交给生成方。
`literal_hints`、`term_hints` 仅作评审检索参考，不是新的用户要求。
历史模式用 `--contract-mode legacy`；无模式字段的历史记录按 legacy 读取，
其保留清单放入 `review_reference`，不得仅因违反生成方没见过的清单而判严重遗漏。
严重遗漏须同时由原文与实际任务证明。混合可见性模式不能生成同一对比包。
评分维度、权重和 rubric 1.0.0 不变；旧输出和旧评分不覆写。

实验记录同时保存 `model_requested` 与 `reasoning_effort_requested`。
例如 `--model gpt-6-astra --reasoning-effort medium`。这两个参数记录请求，
不会替适配器设置模型；执行者必须在模型调用或子 Agent 配置中同样指定。
报告应分别注明生成模型、评审模型、推理档位、配置来源及服务端身份是否独立验证。
未知值写未核实，不从当前配置倒填历史实验。
